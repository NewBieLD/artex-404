# SRC 报告去腔

只用于正式报告里「漏洞描述」「漏洞危害」「修复建议」三段散文。没有本文件则跳过。

## 0. 覆写

- 不动：标题三行、标签冒号、全角＃、接口清单、raw HTTP、sqlmap 行。
- 与 `/home/lotso/artex-ymh/skills/src-method-pack/rules/vuln-report-format.md` 冲突时 **以 format 为准**。
- 不追问用户要材料，不读论坛/小说写法，不跑检查脚本。
- 这三段散文里少用破折号和提示性冒号（「一句话总结：」「核心是：」）。标签行和 HTTP 包里的冒号一律不动。

## 1. 这三段禁止的腔

- 翻案腔：先立一个读者没有的误解再推翻。外衣包括「不是A而是B」「并非…而是…」「与其说…不如说…」「你以为…其实…」「说到底」。从正面下判断，依据放旁边。
- 三项以上同构排比。两项为限。
- 抽象名词配具体动词抒情（时间保管细节、焦虑显形）。还原成人做了什么。
- 名词化套话：「完成了对…的优化」「实现了…提升」→ 写成做成了啥。
- 「说白了」「说穿了」「先说结论」。
- 洞察路标：「更微妙的是」「值得注意的是」「需要指出的是」「从某种意义上说」用来抬段时删。
- 黑话：赋能、抓手、闭环、底层逻辑、顶层设计、降本增效、全链路、组合拳 等。改成人、动作、后果。
- 说明书腔、「攻击者」。描述用「我」说做成了啥。

## 2. 怎么改

找到原句要下的判断，从正面说出来，依据放旁边。不要换成另一套漂亮句式。

危害每种伤害单独一行；有例子举实值；没打过的不编。改腔不得删事实、实值、权限面。

## 3. 冲突

format 的标签必须带冒号（`漏洞描述：`）。禁止把「散文少用冒号」套到标签行和整包。
